# 🛠️ Problem Learning Coach (problem-learning-coach)

> **拒绝玩具代码。把大模型重塑成成长的工业级技术导师。**

---



## 🎯 为什么发明这个项目？

在日常开发或带新人的过程中，新人面对项目里大段的代码，最大的痛点往往是：**“大体看得懂，但卡在某一个特定机制（如异步状态、网络拦截、协议断帧）上，不知道数据是怎么流动的，更不敢在原项目里乱改。”**

如果直接去网上找公开的 Demo，往往跟当前项目的技术栈、依赖版本对不上，参考价值极低。而普通的 AI 助手在解释代码时，又容易急于给出大段复杂的最终代码，甚至自动在本地创建一堆临时文件，搞脏了 Git 工作区。

**`problem-learning-coach` 是一个专为“局部参考与流程学习”设计的提示词框架。** 它秉持“不碰源码、纯文本沉淀”的理念，逼着大模型在唯一的 Markdown 文档里，为新人搭建一个极度干净的、剥离了业务噪音的“局部代码图纸”。

同时，它现在支持一个清晰的**模式路由**：默认仍然是学习 SKILL；只有用户明确说“项目模式”或“考察/测试模式”时，才切换到对应模式。这样既保留学习 SKILL 的原始教学能力，又能复用项目分析和项目考察能力。

---

## 🧭 模式路由（Mode Routing）

本 SKILL 的入口规则很简单：**不指明模式就学习；指明模式就切换。**

| 用户说法 | 执行模式 | 交付位置 | 行为 |
| --- | --- | --- | --- |
| `走学习SKILL`、`用学习SKILL讲一下这个问题`、未声明任何模式 | 学习模式 | `docs/learn/LyyyyMMdd(主题).md` | 按学习 SKILL 原流程讲解问题、生成学习文档、等待用户确认后追加最小化 demo |
| `走学习SKILL项目模式`、`用学习SKILL走项目模式`、`学习SKILL 项目模式` | 项目模式 | `doc/project/PyyyyMMdd(项目或模块分析).md` | 不走学习文档流程，读取 `references/project-mode.md`，按项目分析三阶段梳理项目 |
| `走学习SKILL考察模式`、`学习SKILL考察模式`、`学习SKILL测试模式`、`测试模式`、`项目测试模式`、`进入考察模式`、`你考我一下` | 测试模式 / 考察模式 | `doc/project/PyyyyMMdd(项目或模块分析).md` | 不走学习文档流程，读取 `references/rules/inspection-mode.md`，一次只问一个项目理解问题并等待用户回答 |

### 默认学习模式

当用户只说“走学习 SKILL”或者只是要求解释某个技术问题时，AI 必须执行 `SKILL.md` 里的学习流程：

- 只读项目源码。
- 生成或追加 `docs/learn/LyyyyMMdd(主题).md`。
- 先做“阶段一：讲解原理”。
- 等用户确认学习重点后，才追加“阶段二：学习最小化 demo”。
- demo 只写进 Markdown 文档，不创建真实 demo 工程。

### 项目模式

当用户明确说“项目模式”时，学习 SKILL 只作为入口，不再执行学习文档流程，而是读取：

```text
references/project-mode.md
```

项目模式用于系统级项目理解，输出到：

```text
doc/project/PyyyyMMdd(<项目或模块名>分析).md
```

它按原项目分析 skill 的阶段执行：

1. 阶段一：宏观拓扑（L1-L2）
2. 阶段二：领域模块（L3）
3. 等用户回复 `继续` 后，再进入阶段三：业务场景驱动理解（L4）

### 测试模式 / 考察模式

当用户明确说“考察模式”或“测试模式”时，它是项目模式下的子模式，不是学习模式下的 demo 阶段。AI 会读取：

```text
references/project-mode.md
references/rules/inspection-mode.md
```

进入测试模式后，第一轮回复必须**只输出第 1 个问题**，然后停止等待用户回答。用户回答后，AI 才能评分、指出足和不足、给参考答案，并继续问下一题。

如果已有项目分析文档，考察记录会追加到同一份 `doc/project/PyyyyMMdd(<项目或模块名>分析).md` 的 `# 考察模式` 章节。若还没有明确项目分析上下文，AI 应先检查当前项目或提出必要澄清，不能凭空编问题。

## 🧱 核心设计原则

本 SKILL 能够切实帮助新人看懂流程、拿到有效参考，得益于以下几条纯粹的学习约束：

### 1. 🛑 绝对的零侵入性（Hard Safety Rule）
本 SKILL 绝不具备任何开发或代码重构功能。在执行过程中，原项目源码只读。**严禁在本地创建任何真实的 Demo 文件夹、脚本或实体代码文件。** 所有的参考代码和目录结构，必须以**纯文本代码块**的形式，追加（Append）在唯一的交付文档 `docs/learn/Lyyyyymmdd(主题).md` 中。保持工作区绝对纯净。

### 2. 🧩 剥离业务噪音的“最小化参考图纸”
当教学某个局部机制（如 NMEA 协议解析、网络 Token 刷新）时，AI 会砍掉原项目里所有无关的业务外壳（如权限校验、数据库审计等），用最干净的工程结构（哪怕用 Mock 数据）在 Markdown 里展示出来。新人的注意力可以 100% 聚焦在核心流程上，需要的时候可以直接照着这个 Demo 结构进行本地复刻。

### 3. 🛠️ 尊重基础工程素养（No Scaffold Provide）
本 SKILL 在图纸和代码因果关系的解释上极其详尽，但**绝对不会提供任何一键初始化的脚手架命令或自动构建脚本。** 新人如果想要在本地跑一下这个参考 Demo，必须自己建文件夹、自己配环境、自己处理本地工具链的报错。本框架只负责把“逻辑流程”讲得清清楚楚，而“搭建环境并让它跑起来”这一步基础的折腾，留给新人自己完成。

### 4. 📝 全语句逐行因果注释
在 Demo 代码块中，每一行有效的执行语句、配置声明上方，必须紧跟一条中文注释。注释只能写在对应代码的上一行，不能写成同一行尾注释。注释不仅要写“这行代码在干嘛”，更要写明**“为什么要配在这里”** 以及 **“如果删掉或配错会引发什么后果”**。把复杂的隐性知识变成新人一眼就能看懂的白话说明书。

## 🔄 三阶段学习心流（Execution Phases）

本框架通过“通关挂起”机制，确保学习过程循序渐进：

* **阶段一：讲解原理** ──> 在 MD 文档中理清概念、数据流向图和核心原项目代码。给出 2-5 个局部的进阶学习方向，**卡点挂起**，等待用户确认。

* **阶段二：学习最小化demo** ──> 用户确认想深入参考的主题后，AI 在同文档内追加 100% 完整的纯文本工程代码块，并划清“做足的地方和故意简化的边界”，作为新人的随手查阅积木。

* **阶段三：追加学习最小化demo** ──> 支持“无限续杯”。新人如果顺着思路产生了衍生盲区，可以直接说“追加学习 XXX”，AI 会在同一份文档末尾继续 Append 新的参考图纸，不破坏前面的记录。

  **没有用AI直接生成最小化项目而是在文档中体现，是因为生成文档在复制运行配置等过程必不可少也是看代码学习的关键要素**

## 📂 沉淀出来的学习文档结构（Output Shape）

每一个被本框架引导生成的文档，都是一份完美的“技术备忘录/参考图纸”，结构如下：

```markdown
# 标题（规范命名：Lyyyyymmdd(主题).md）

> 目标读者：需要理解该局部机制的开发者
> 阅读目标：快速理清数据流程，在需要时作为干净的工程积木进行参考

## 1. 一句话讲清楚
## 2. 这个问题在项目里是什么
## 3. 架构和流程（Mermaid 数据流向/调用栈拓扑图）
## 4. 易踩坑和优秀实践（✔）
## 5. 潜在不足与演进（×）
## 6. 类似设计推荐
## 7. 核心代码以及注释（原项目只读引用）
## 8. 接口或运行说明
## 9. 学习重点确认 🛑（AI 在此卡住，等待确认下一步想拿来参考的具体 Demo 主题）

------------【用户确认主题后，AI 纵向追加的内容】------------

## 10. 最小化demo（关于XXX）
## 10.1 demo 技术栈和完整性说明（明确折腾边界）
## 10.2 企业级规则判断（说明生产级与教学级的区别）
## 10.3 基于 demo 的架构图
## 10.4 按开发顺序展示文件内容（提供【所属路径】与行行带后果的详细注释）
## 10.5 手动运行命令、预期结果和原项目对应关系
## 10.6 做足的地方和不足（划清 Demo 的参考边界，防止盲目照抄）
## 11. 下次遇到怎么判断

## 12. 追加学习：YYY（支持续杯，纵向滚雪球扩展）
## 13. 最小化demo（关于YYY）
```

## 🚀 如何使用？

1. 在你的项目根目录下创建 `.cursorrules`、`SKILL.md` 或者直接将其作为系统提示词（System Prompt）常驻在你常用的 AI 助手（如 Gemini, Cursor, Claude）中。

2. 将本项目提供的 `problem-learning-coach` 提示词全文复制进去。

3. 当新人对项目里的某段晦涩逻辑（如：Dio 拦截器 401 刷新、Kafka 幂等消费、NMEA/RTCM 协议断帧等）看不懂时，直接对 AI 发起提问：

   > *“帮我用 problem-learning-coach 梳理一下这段代码的逻辑，我想生成一份学习文档。”*

4. 如果想切换模式，直接在请求里说清楚：

   > *“走学习SKILL项目模式，分析这个项目。”*

   > *“走学习SKILL考察模式，你考我一下。”*

5. 顺着 AI 的阶段提示，开启硬核的图纸复刻学习之旅；进入项目模式或考察模式时，则按对应模式的阶段规则推进。
